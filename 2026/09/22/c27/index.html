vite dev与preview的区别

文章发布时间:
2026-09-22

最后更新时间:
2026-09-23

./node_modules/.bin/vite 启动的是 开发服务器；
./node_modules/.bin/vite preview 启动的是 生产构建产物的本地预览服务器。

| 对比项 | ./node_modules/.bin/vite | ./node_modules/.bin/vite preview |

| 实际命令 | 默认等于 vite dev / vite serve | vite preview 子命令 |

| 用途 | 开发调试 | 本地预览 vite build 的结果 |

| 服务内容 | 你的源码，按需编译 | 已构建的静态文件，默认是 dist/ |

| 是否需要先构建 | 不需要 | 需要先执行 vite build |

| HMR 热更新 | 支持 | 不支持 |

| 默认端口 | 5173 | 4173 |

| 修改源码后 | 自动编译、浏览器更新 | 不会自动重新构建，需要重新 vite build |

| 能否用于生产 | 不能 | 不能，只是本地预览 |

是预览服务器，适合构建完成后检查 dist/ 里的产物是否正常。它不会帮你构建；如果还没运行 vite build，通常会提示找不到 dist 目录或页面不正常。

另外，vite preview 不是生产服务器，线上部署一般用 Nginx、Caddy、Node 静态服务等托管 dist/。

你维护的，是源代码——js/、css/ 那些，文件多、好读、用名字 import。 真正上线运行的，是 dist——文件少、经过压缩、改了名，是浏览器认得的形态。

由此可得几个直接的结论：

改网站永远改源代码，然后重新 build。不要手动改 dist 里的文件——下一次 build 就会把它覆盖掉。
dist 才是真正要送上线的那一份。 dev 用于”写代码时”（运行源码 + 热更新，图改得快）；build 产出的 dist 才是”给生产服务器运行的版本”。也就是说——下一个模块（4.6 部署）真正推上线的，正是这种 dist。preview 只是上线前在本地先验一眼。
