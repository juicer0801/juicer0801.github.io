第 8 节：自动微分

线性代数负责前向传播，微积分负责反向传播。但到目前为止，梯度都是手动算的，或者用 backward() 。

8.1 为什么要自动微分

求导的计算本身很简单，只需要一些基本的微积分知识。但对于复杂的模型，手工进行更新是一件很痛苦的事情，而且经常容易出错。

先用 NumPy 写一个多项式拟合的例子。

注意看梯度那几行。这只是一个三阶多项式，只有一个输入特征，梯度公式就已经长这样了。如果换成多层神经网络，几百个参数，每一层的激活函数还不一样，手推梯度基本不可行。而且改一下网络结构，所有梯度公式都要重来。

根据设计好的模型，系统会构建一个计算图来跟踪计算是哪些数据通过哪些操作组合起来产生输出，自动微分使系统能够随后反向传播梯度。

backward()靠计算图的作用。

前向传播的时候，PyTorch 不只算出结果，还把每一步运算记录下来，构成一张有向无环图。图的叶子是输入张量，根是输出张量。反向传播的时候，从根出发，沿图反向走，用链式法则一层层算梯度。

例子：

前向传播构建的图是：

反向：

  • (c) 对 (b) 的梯度：(\frac{dc}{db} = 2b = 14)
  • (b) 对 (a) 的梯度：(\frac{db}{da} = 1)
  • (a) 对 (x) 的梯度：(\frac{da}{dx} = 3)
  • 乘起来：(14 \times 1 \times 3 = 42)

每个张量都有一个 grad_fn 属性，指向创建它的运算。这就是计算图的“反向边”：

grad_fn 串起来就是整张计算图。backward() 沿着 grad_fn 链反向走，每一步调用对应的反向函数，把梯度传下去。

叶子节点是用户直接创建的张量，grad_fn 永远为 None。中间由运算产生的张量，grad_fn 不为 None grad_fn 指向创建它的运算。

PyTorch 的 autograd 机制有一个重要的设计特点：计算图在每次迭代中都是从头重建的，这正是它能够使用任意 Python 控制流语句的原因。你不需要事先编码所有可能的路径——运行什么，就微分什么。

这个机制叫向量-雅可比积（Vector-Jacobian Product，VJP）。反向传播真正算的不是完整的雅可比矩阵，而是雅可比矩阵转置乘以一个向量。这个向量就是 backward() 的参数。

8.5 分离计算

有时候我们不想让某个张量参与梯度计算。PyTorch 提供了几种方式。

detach()

detach() 返回一个跟原张量共享数据、但不跟踪梯度的新张量：

书里举了一个更具体的例子。假设 y 是作为 x 的函数计算的，而 z 则是作为 y 和 x 的函数计算的。如果想计算 z 关于 x 的梯度，但希望将 y 视为一个常数，只考虑 x 在 y 被计算后发挥的作用，可以分离 y 来返回一个新变量 u，该变量与 y 具有相同的值，但丢弃计算图中如何计算 y 的任何信息。

因为 u 被当作常数，z = u * x 对 x 的偏导数就是 u，也就是 x²。

detach 和 no_grad 的区别

  • detach() 是对已经计算出来的张量做处理，把它从计算图里摘出来。
  • no_grad() 是对即将进行的运算做处理，让这些运算不构建计算图。

8.6 一个完整的训练循环

前向、算损失、清零、反向、更新——是所有 PyTorch 训练代码的骨架。

optimizer.zero_grad() 对应梯度累积问题。loss.backward() 对应计算图和链式法则。optimizer.step() 里面用了 no_grad()分离计算。

8.7 梯度累积：一个实用案例

zero_grad() 要放在循环开头。PyTorch 默认会累积梯度，不清零的话梯度会一直加下去。这个特性有时候是麻烦，有时候却很有用。

假设你只有一张 8GB 显存的显卡，想训练一个需要 64 batch size 的模型，但显存只够跑 16。这时候可以用梯度累积——跑 4 个 mini-batch，累积梯度，再做一次参数更新，等价于 64 的 batch size。

注意 loss = loss / accumulation_steps ，梯度会变成原来的 4 倍，相当于学习率变大了 4 倍

8.8 自动微分的意义

手动求导的问题不在于难，而在于改结构就要重推。

用 NumPy 写一个三阶多项式拟合，梯度公式还能手推。但如果换成十层神经网络，几百个参数，每一层的激活函数还不一样，手推梯度基本不可行。改一下网络结构，所有梯度公式都要重来。

自动微分解决了这个问题。你只需要写前向传播，反向传播由框架自动生成。网络结构随便改，激活函数随便换。

这就是为什么 PyTorch、TensorFlow、JAX 这些框架都把自动微分作为核心功能。

本节小结

  • 自动微分是框架自动计算梯度的机制，核心是计算图和链式法则。
  • 计算图在前向传播时构建，记录每一步运算。反向传播沿图反向走，用链式法则算梯度。
  • 叶子节点是用户直接创建的张量，grad_fn 为 None。中间结果的 grad_fn 指向创建它的运算。
  • 非标量输出需要传入梯度参数，本质是向量-雅可比积。
  • detach() 把张量从计算图里摘出来，返回共享数据但不跟踪梯度的新张量。
  • torch.no_grad() 让一段代码不构建计算图，用于推理和参数更新。
  • 梯度会累积，每次反向传播前要手动清零。反过来，这个特性可以用来实现梯度累积，在小显存上模拟大 batch size。
  • 反向模式适合输入多输出少的情况，是深度学习的默认选择。
