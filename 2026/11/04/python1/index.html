在 Python 里，只要你实现了 __getitem__ 这个特殊方法，Python 解释器就会自动地免费送你一大堆强大的功能。

这叫协议（Protocol）或者鸭子类型（Duck Typing）——“只要它走起来像鸭子，叫起来像鸭子，那它就是鸭子”。（经典名言hhh）

1. 自动支持“切片”（Slicing）

我只写了 __getitem__（获取单个元素），但当我写 deck[1:3]（切片）时，代码居然没报错，直接返回了牌！

底层原理：
当我对对象使用切片语法时，Python 会自动调用 __getitem__。这时的参数不再是整数 0, 1, 2，而是一个 slice 对象（比如 slice(1, 3, None)）。
因为你在 FrenchDeck 的 __getitem__ 里写的是 return self._cards[position]，你把 slice 对象直接传给了底层的列表 self._cards。列表天生支持切片，所以我的扑克牌类也就白嫖了切片功能。

那个 deck[12::13] 是什么意思？
基础复习：[start:stop:step]。
起点是 12（第一张 A，黑桃 A），步长是 13。13张牌是一组花色，所以跳 13 张拿一张，刚好把 4 张 A 全抽出来了。

2. 自动支持“循环遍历”（Iteration）

看图中部的代码：

我没有定义 __iter__ 方法，凭什么能直接用 for 循环？
底层原理：
当 Python 遇到 for x in my_object 时，它第一反应是找对象的 __iter__ 方法。找不到怎么办？
Python 解释器会退而求其次：它发现我有 __getitem__，于是它就会像入机一样，从索引 0 开始，一直调用 deck[0], deck[1], deck[2]……直到抛出 IndexError 异常为止。
同样，reversed(deck)（反向迭代）也是如此。如果没有 __reversed__ 方法，Python 会尝试利用 __len__ 和 __getitem__ 倒着取值，实现反向遍历。

3. 自动支持 in 运算符（Membership）

发生了什么？
我也没有写 __contains__ 方法，为什么可以用 in 来判断一张牌在不在牌堆里？
底层原理：
当 Python 执行 x in my_object 时，会找 __contains__。找不到的话，它会再次退而求其次，利用 __getitem__ 进行顺序扫描。
也就是说，它会通过 __getitem__ 把牌堆从头到尾拿一遍，挨个跟我找的那张牌比对，直到找到（返回 True）或者找完都没有（返回 False）。

(不过要注意，由于没有 __contains__，这种顺序扫描的效率是 O(n) 的，比起原生列表的 in 操作可能要慢。)

总结ing：

这就是 Python 数据模型（Data Model） 的威力。
写一个类，只要顺着 Python 的规矩，实现了特定的“魔术方法”（双下划线方法），Python 就会自动帮你把切片、迭代、in 判断等基础功能全配齐，一行额外的代码都不用写。

“借力打力，少写代码”，这就是 Pythonic（有 Python 味）的编程方式。

一、 顶部代码：如何按规则给扑克牌排序？

这里用到了 Python 内置的 sorted() 函数，并且传入了 key 参数。
sorted() 默认是没法给 Card 对象排序的（因为它不知道两张牌谁大谁小）。所以它需要你提供一个“裁判”（即 key=spades_high），每次拿一张牌，裁判告诉它一个数字，最后 sorted 根据这个数字从小到大排。

spades_high
这是一个非常巧妙的加权打分算法：

  • FrenchDeck.ranks.index(card.rank)：找到这张牌的点数在列表 ['2', '3', ..., 'K', 'A'] 里的索引。比如 2 是 0，A 是 12。
  • rank_value * len(suit_values)：suit_values 有4个花色，所以长度是 4。这就把点数放大了。比如 2 算出来是 0，3 算出来是 4，A 算出来是 48。
  • + suit_values[card.suit]：加上花色的权重（黑桃3，红桃2，方块1，梅花0）。

举个例子：

  • 黑桃 A = 12 * 4 + 3 = 51（最大）
  • 红桃 A = 12 * 4 + 2 = 50
  • 黑桃 2 = 0 * 4 + 3 = 3
  • 梅花 2 = 0 4 + 0 = 0（最小）
    通过这个简单的数学算式实现了*“先比点数，点数一样比花色”    的规则。

二、 为什么是“组合”，而不是“继承”？

“虽然 FrenchDeck 类隐式继承 object 类，但是前者的多数功能不是继承而来的，而是源自数据模型和组合模式。”

基础不牢的喵喵，可能会喵：既然我是一副牌，里面装的是列表，我为什么不直接让 FrenchDeck 继承 list 呢？

  • 继承（Inheritance）：class FrenchDeck(list):。这样确实能直接用 append、pop 等等方法。但坏处是，它会把列表的所有方法都暴露出来。别人可以随便往你的扑克牌里加一个“苹果”或者“字符串”，这就不符合逻辑了。
  • 组合（Composition）：FrenchDeck 内部有一个 self._cards（是一个列表）。这叫把列表当作一个鱼干吃进自己的肚子里了喵。
  • 好处：你只挑你想要的特性（用 __len__ 代理长度，用 __getitem__ 代理拿牌）。别人不能改我肚子里的小鱼干————封装性更好。

三、 “如何洗牌？”（不可变性）

书上说不能对 FrenchDeck 洗牌。
为什么？因为只实现了 __len__ 和 __getitem__，我只给了别人“看”和“拿”的权利，没给“改”的权利。
如果别人写 deck[0] = Card('A', 'spades')，Python 会直接报错，因为没有实现 __setitem__ 方法。
(书里说第13章会加 __setitem__ 解决这个问题，这里先埋个坑。)

四、 1.3 特殊方法是如何使用的（重点）

这一小节讲的是 Python 的底层逻辑和性能优化。

1. 有些新喵可能会直接调用 __len__
在写代码时，千万不要写 my_object.__len__()。
正确的写法是：len(my_object)。
为什么？因为 len() 是 Python 的内置函数（C语言实现的）。当你调用 len() 时，Python 解释器会直接去对象底层的 C 结构体（PyVarObject）里读取一个叫 ob_size 的字段（存着元素的个数）。这个速度超级快，比调用方法快得多。

2. for 循环
之前说过，你只写了 __getitem__，凭什么能 for i in x:？
书上解释了：for i in x: 背后其实是在调用 iter(x)。如果 x 没有 __iter__ 方法，Python 就会退一步，利用 __getitem__，从索引 0 开始，配合一个计数器，不停地去拿数据，直到抛出 IndexError。
(但注意：这种依靠 __getitem__ 的迭代是后备方案，效率不如直接定义 __iter__。)

3. __init__ 是个例外
绝大多数双下划线方法（比如 __len__、__getitem__）都是解释器偷偷调用的（隐式调用），但 __init__ 是个例外。
在写 deck = FrenchDeck() 的时候，其实是显式地触发了 __init__ 来给对象做初始化。这是代码编写中最常见的直接调用特殊方法的情况。

总结ing：

  1. 怎么用 sorted 的 key 配合自定义函数来实现复杂的多重条件排序。
  2. “组合（把对象装进去）”通常比“继承（变成子类）”更安全、更灵活。
  3. len() 为什么比调用 .__len__() 快（底层 C 语言优化），以及 for 循环如果没有 __iter__ 会怎么利用 __getitem__ 后位替代

第二块：让对象“更好看”（右侧 1.3.2 __repr__）

新手经常搞混 __repr__ 和 __str__。

看代码里的 __repr__：


它有什么用？
如果你在控制台（终端）里直接输入一个对象名按回车，Python 就会调用这个对象的 __repr__ 方法，把结果展示给你。它是用来给开发者看的，主要用于调试。
所以它的目标应该是精准，最好长得像你创建它的代码，比如 Vector(1, 2)。那个 !r 是 repr() 的简写，保证打印出来的是带引号或者原本的样子。

那 __str__ 呢？
__str__ 是给用户看的（比如用 print() 打印的时候）。

  • __repr__ 就像是程序员查错的报告，要详细。
  • __str__ 就像是给用户看的说明书，要好看。
    如果你只写了 __repr__ 没写 __str__，Python 在 print() 时会走投无路，“退而求其次”直接借用 __repr__ 的结果。

第三块：内置函数的魔法（左侧 __abs__ 和 __bool__，右上角 1.3.3）

看代码里的这两个：


1. __abs__ 的妙用：
内置函数 abs() 本来是求绝对值的（比如 abs(-5) 等于 5）。对于向量来说，求“模长”（向量的长度）最合适了。所以当你写 abs(v) 的时候，Python 就去调用了 __abs__，里面用勾股定理（math.hypot）算出了向量的长度。

2. __bool__ 决定对象是“真”还是“假”：
在 Python 里，如果你写 if v:，解释器怎么知道这个 v 是真还是假呢？
它会去找 __bool__ 方法。这里定义了：如果这个向量的长度（abs(self)）不是 0，那就是 True；如果长度是 0（也就是原点），那就是 False。

右上角 1.3.3 补全（书上没写完）：
书右上角说，如果你没写 __bool__ 怎么办？
Python 会接着找 __len__（跟之前学的一样）。如果长度为 0，布尔值就是 False。
如果 __bool__ 和 __len__ 你都没写，那么不管你类里装了什么，只要对象存在，布尔值就永远是 True。

这一页可以说是让你从“会用 Python”向“懂 Python 哲学”跨越的一页。
通过简单的魔术方法，你写的 Vector 可以像列表一样相加、像数字一样相乘，可以用 print() 打印好看的样子，可以用 abs() 算长度，还能放在 if 语句里做判断。这一切，都归功于“数据模型”的统一设计。
