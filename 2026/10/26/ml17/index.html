一、时间序列预测简介

1.什么是时序预测

时间序列预测是一种根据历史时间序列数据来预测未来值的方法。

任务比较好理解，但预测未来并非易事。

4.算法的选择

4.1基于统计学的经典时序预测算法【了解】

  • 统计朴素法：今天的值作为明天的预测值

  • 简单平均法：历史上所有值的平均值作为明天的预测值

  • 移动平均法：历史上一段时间窗口内的平均值作为明天的预测值

  • 简单指数平滑法：历史上的值加权平均作为明天的预测值，加权方法是指数方式（保证近期权重更大，远期权重更小）

  • 霍尔特(Holt)线性趋势法：一个水平方程（Lt），一个趋势方程（Bt），再把二者计算的结果加起来

  • AR自回归模型：历史上一段时间窗口内的值预测出明天的预测值

  • MA移动平均模型：均值加上白噪声项

  • ARIMA差分自回归移动平均模型：自回归与移动平均结果之和

    注：以上基于统计学的时序预测算法，使用时需要进行平稳性检验，模型本身进行了平稳性假设与白噪声假设，存在局限性，且通常准确性相对机器学习模型会低。

时间戳:

核心目的：获取系统当前时间，将其格式化为一串纯数字，拼接成独一无二的文件名（例如：train_20231027153045.log），常用于日志记录，防止文件互相覆盖。

  1. import datetime
    • 导入 Python 内置的时间处理模块，不需要额外安装第三方库。
  2. now = datetime.datetime.now()
    • 获取当前的系统时间对象（包含年月日时分秒）。
    • 注意：这里只调用了一次。如果在拼接字符串时多次调用，一旦程序刚好跨越了“秒”的边界，会导致前后时间不一致，产生Bug。
  3. now.strftime('%Y%m%d%H%M%S')
    • 将时间对象按照指定的格式转换为字符串（string format time）。
    • 格式指令说明：
      • %Y：4位年份（如 2023）
      • %m：2位月份（01-12）
      • %d：2位日期（01-31）
      • %H：2位小时（00-23，24小时制）
      • %M：2位分钟（00-59）
      • %S：2位秒数（00-59）
    • 效果：2023-10-27 15:30:45 变成了纯数字的 20231027153045，因为纯数字作为文件名最安全（不会出现空格或特殊符号导致的报错）。
  4. 'train_' + ... + '.log'
    • 利用 + 号进行字符串拼接。最终得到形如：train_20231027153045.log 的文件名。

  • pd.to_datetime(...)：将原本可能是字符串格式的时间（如 "2013-09-17 10:00:00"）转换为 Pandas 标准的 datetime 时间对象。

  • drop_duplicates(inplace=True)：
    • 默认情况下，它会检查所有列的值，只有当所有列的值完全一致时，才会判定为重复行并删除。

知识点与坑

  1. 子图布局 fig.add_subplot(411)

    • 数字 411 的含义是：将画布分为 4 行 1 列，当前激活的是第 1 个子图。同理，412 是第 2 个，413 是第 3 个，414 是第 4 个（从上往下排）。

  2. 字符串切片提时间

    • 代码中使用了 str[11:13] 提取小时，str[5:7] 提取月份。这依赖于 time 列必须是标准的字符串格式（如 '2013-09-17 10:00:00'）。

  3. ⭐ 更优雅的时间提取方式（强烈推荐）

    • 如果你的 time 列已经被转换成了 Pandas 的 datetime 对象（参考前面的 pd.to_datetime），不需要用字符串切片，可以直接用 .dt 访问器，速度更快且更安全：
      • 提取小时：data['time'].dt.hour
      • 提取月份：data['time'].dt.month
      • 判断星期几：data['time'].dt.weekday (周一为0)

  4. groupby 的 as_index=False

    • 分组求均值时，默认会将分组字段（如 ‘hour’）变成行索引（Index）。加上 as_index=False 后，它会重新变成一个普通的列，这样你在后面画图传入 x=data_hour_avg['hour'] 时就不会出现错位或找不到列的问题。

  5. 保存图片的坑

    • 原代码的 plt.savefig('../data/fig/负荷分析图.png') 如果前面的目录（../data/fig/）不存在，程序会直接报 FileNotFoundError 崩溃。在工程中，最好提前用 os.makedirs('../data/fig/', exist_ok=True) 确保文件夹存在。

注释代码

知识点与坑

  1. 时间切片 .str[11:13] 的隐患
    • 代码使用切片提取小时和月份。这强依赖于你的 time 列格式必须是严格的字符串 'YYYY-MM-DD HH:MM:SS'。如果格式变了（比如变成了 '2013/09/17'），切片就会错位。建议先 pd.to_datetime 转换，然后使用 .dt.hour 和 .dt.month 更稳妥。
  2. shift() 的 NaN 问题
    • shift(1) 会把第一行变成空值，shift(3) 会空出前三行。由于时间序列模型的输入要求完整，必须通过 dropna() 剔除这些空行。
  3. 字典映射代替 merge（高级技巧）
    • 代码中 time_load_dict = result.set_index('time')['power_load'].to_dict() 是非常经典的做法。因为直接用 DataFrame.merge 匹配昨日数据不仅代码长，而且性能低。转成字典后，用 apply 查找是瞬间完成的。
  4. One-Hot 编码的维度爆炸
    • pd.get_dummies 会把小时（24维）和月份（12维）展开成 36 个新列。对于树模型（如 XGBoost, LightGBM）这没问题；但如果特征本身很多，可能会导致特征维度爆炸，需要考虑降维或改用周期性数值（如 sin/cos 编码）。
  5. 缺失值处理放在最后
    • 这是因为前面的所有特征提取（滑动窗口、查字典）都会引入新的缺失值，放在最后统一 dropna 最安全。

API 速查字典

  • pd.get_dummies(Series)
    • 功能：进行独热编码（One-Hot Encoding）。将分类变量（如月份 ‘1’-‘12’）转换为 0/1 矩阵。适合用来把类别数据“散开”给模型看。
  • pd.concat([df1, df2], axis=1)
    • 功能：拼接数据。axis=1 表示横向合并（增加列）。axis=0 表示纵向合并（增加行）。常用于把新生成的特征拼回主表。
  • Series.shift(i)
    • 功能：将数据向下移动 i 行。在时间序列中，shift(1) 就是取“上一时刻”的数据，用来构造“滞后特征（Lag Feature）”。
  • Series.set_index('列名').to_dict()
    • 功能：将指定列作为字典的 Key，其他数据作为 Value，生成一个 Python 字典。常用于快速查找匹配数据，避免繁琐的表格关联（Join/Merge）。
  • pd.to_timedelta('1d')
    • 功能：生成一个时间差对象。'1d' 表示 1 天。常和 datetime 结合做时间的加减运算。
  • DataFrame.dropna(axis=0, inplace=True)
    • 功能：删除缺失值。axis=0 表示如果这一行有任何一个空值，就把这一整行删掉。inplace=True 表示直接在原数据上修改。
  • list(hour_encoding.columns)
    • 功能：获取 DataFrame 的所有列名，并转换为 Python 原生列表，方便后续将特征名字符串列表传给模型或日志记录。

知识点
  1. MSE 与 MAE 的区别（原代码注释有个小Bug）
    • 原代码第 4.3 步注释写的是 MSE、MAPE，但代码实际用的是 mean_absolute_error（MAE）。MAPE（平均绝对百分比误差） 需要用 mean_absolute_percentage_error。
    • MSE（均方误差）：对异常值极其敏感（因为误差被平方了），如果有一个预测错得离谱，MSE 会瞬间飙升。
    • MAE（平均绝对误差）：反映了预测值误差的实际情况，单位与目标值一致（比如单位都是“千瓦”），更直观。
  2. 训练集 vs 测试集的表现差异
    • 过拟合（Overfitting）：如果训练集 MSE 极低，但测试集 MSE 很高，说明模型“死记硬背”了训练集，泛化能力差。
    • 通常，测试集的误差会略高于训练集，这是正常的。如果相差过大，需要减少模型复杂度（如减小 max_depth）或增加正则化参数。
  3. 网格化搜索的取舍
    • GridSearchCV 是全量穷举，虽然能找到最优解，但计算量极其庞大（例如 4×3×2=24种组合 × 5折交叉验证 = 训练120次模型）。
    • 在实际工程中，通常先手动调几个参数跑一下，或者用 RandomizedSearchCV（随机搜索）来节省时间。
  4. 模型保存的格式
    • joblib.dump() 保存的 .pkl 文件是 Python 的序列化对象。它的优点是极速且无损；缺点是存在版本兼容问题（如果训练环境的 XGBoost 版本和部署环境的版本不一致，可能会报错或预测异常）。

数据演变与逻辑

假设我们要预测的时间 time 是 '2024-12-20 09:00:00'。

  1. 小时特征截取：pred_hour = time[11:13] 得到 '09'。
    • 循环 24 次。当循环到 hour_09 时，feature_names[i][5:7] 也是 '09'。匹配成功！hour_part 的列表第 10 个位置（索引9）填入 1，其余填 0。
  2. 月份特征截取：pred_month = time[5:7] 得到 '12'。
    • 循环比对，在 month_12 的位置填入 1，其余填 0。
  3. 历史特征查询：

  4. 组装数据：hour_part (24个0/1) + month_part (12个0/1) + his_part (4个负荷数值) = 共 40 个特征。
  5. 格式化：将这些数据放进一个两层嵌套的列表 [[...40个数据...]]，转换成 1 行 40 列的 feature_df。
知识点
  1. 单条预测不能再用 pd.get_dummies：
    训练时我们用了 pd.get_dummies 对全量数据展开。但在预测时，如果只有一条数据（比如只有9点的数据），get_dummies 就只会生成 hour_09 这一列，其他 23 小时全没了，模型会因为维度不匹配直接报错。所以必须像这段代码一样，手动硬编码实现 One-Hot 映射。
  2. 字符串切片的巧妙复用：
    代码中 feature_names[i][5:7] 用于提取 hour_xx 中的数字，feature_names[i][6:8] 用于提取 month_xx 中的数字。这种写法很取巧，依赖了特征名固定的命名规范。如果以后改了列名（比如叫 hour-09），这里就会全盘崩溃，必须同步修改切片逻辑。
  3. dict.get(key, default) 的重要性：
    在特征工程中，如果直接使用 data_dict[key]，一旦找不到昨天的数据就会抛出 KeyError 导致程序崩溃。使用 .get() 并设置默认值 600，是极其稳健的工程兜底策略。
  4. 二维列表 [[]] 的包装：
    pd.DataFrame 接收一维列表会报错，必须接收二维列表。hour_part + month_part + his_part 是一维列表（长度40），外面套一个 []，变成了二维列表（形状为 1x40），才能顺利转为 DataFrame。

核心数据流与逻辑演变

这段代码最精妙的地方在于 data_his_dict 的动态变化。这也是时间序列预测区别于普通回归任务的根本所在。

假设 pred_obj.data_dict 包含了 8:00 到 12:00 的所有真实负荷数据。

当循环进行到 pred_time = '12:00:00' 时：

  • 字典推导式 {k: v for k, v in pred_obj.data_dict.items() if k < pred_time} 会生成一个新的字典 data_his_dict。
  • 这个新字典只包含 8:00、9:00、10:00、11:00 的数据。
  • 12:00 的数据被“屏蔽”了。
  • 将 data_his_dict 和 pred_time 传给特征解析函数，解析函数只能找到 11:00、10:00、9:00 的负荷（作为前1、2、3小时），以及昨天的负荷。它绝对拿不到 12:00 真实的 power_load。

为什么必须这么做？
如果直接把整个 data_dict 传给解析函数，当你预测 11:00 时，如果有人错误地写了 time + 1h 的逻辑去提取特征，模型就作弊看到了 12:00 的答案。时间序列模型在评估时，必须严格遵守“时间线单向流逝”的物理定律。

知识点
  1. 数据穿越（Data Leakage）—— 时间序列的第一大忌
    • 训练时的随机切分（train_test_split）在时间序列中其实是不严谨的（因为未来的数据可能包含过去的规律）。但在本预测代码中，我们采用了滚动预测（Walk-forward validation）：预测今天，只用昨天及以前的数据；预测明天，只用今天及以前的数据。这是最符合真实业务的模拟。
  2. pred_value[0] 的细节
    • model.predict() 无论输入是一行还是一万行，返回的永远是一个 numpy 数组（例如 [125.4]）。我们要把它存进列表，需要提取出里面的数值，所以用 pred_value[0]。
  3. data_dict.get(pred_time) 的兜底
    • 在 4.4 步中，真实值是用 .get() 获取的。如果 test.csv 中某段时间的数据确实缺失了，这里会返回 None。后续计算 MAE 或画图时，需要提前处理这些 None（例如转化为 np.nan 或用均值填充），否则会报错。
  4. 预测速度问题
    • 因为是单条循环预测（每次只预测一个时间点），如果是预测一整年（8760个小时），循环 8760 次，每次都要转 DataFrame、调模型，速度会非常慢。工程中如果遇到这种需求，要么按批次预测，要么多进程加速。

    • plt.savefig() 是最容易报错的地方。请确保 ../data/fig/ 这个相对路径对应的文件夹在你的运行环境中真实存在。如果不存在，可以用 os.makedirs('../data/fig', exist_ok=True) 提前创建。
  4. mae_score 的业务意义：
    • 假设算出来的 MAE 是 15.3，由于负荷的单位是千瓦（kW），这意味着模型每次预测的结果平均偏离真实值 15.3 千瓦。至于这个误差算不算大，需要结合业务实际水平（比如基准负荷是 1000 还是 100）来判断。
API 速查字典
  • mean_absolute_error(y_true, y_pred)
    • 功能：计算平均绝对误差（MAE）。它的公式是把每个预测值与真实值的差取绝对值，然后求平均。结果与目标变量同单位，非常直观。
  • plt.figure(figsize=(宽, 高))
    • 功能：设置画布大小，单位是英寸。长时间序列图表建议用大尺寸。
  • ax.xaxis.set_major_locator(mick.MultipleLocator(n))
    • 功能：设置 X 轴主刻度的定位器。n 表示每隔 n 个数据单位画一个刻度。常用于防止坐标轴标签过于拥挤。
  • plt.xticks(rotation=角度)
    • 功能：设置 X 轴刻度标签的旋转角度。45 是最常用的倾斜角度，兼顾了可读性和空间节省。
  • plt.savefig('路径/文件名.png')
    • 功能：将当前画板保存为本地图片。必须在 plt.show() 之前调用，否则保存的会是一张空白图。

四、改进方向

1.特征工程角度

  • 优化时间窗口
  • 提取更有效的历史负荷特征
  • 扩展外部特征，比如温度、湿度、风速、历史工业用电量、历史居民用电量等

    2.算法角度

  • 样本分群然后分别建模，比如分地区或者借助聚类算法先进行分群，然后针对不同分区分别训练模型，提升模型的适用性
  • 寻找更优的算法，比如LightGBM、RNN类、iTransformer等算法
  • 寻找更优的算法组合，比如bagging方式或stacking方式进行模型组合

3.预测（推理）速度角度

  • 预测时也需要特征工程处理，历史负荷可以缓存到redis，使用时直接查询

4.扩展性角度

  • 做通用的工具包，适用于各种数据源的输入输出，如mysql、pgsql、oracle、ES、redis、Hive等数据库的支持
  • 项目打包成容器，适配各种服务器环境
  • 预测模块与项目解耦，预测模块封装出接口，接收web传过来的参数，根据参数获取数据并进行预测
